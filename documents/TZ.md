# Техническое задание  
## Разработка автономного зашифрованного мессенджера «Место встречи»

---

### 1. Введение

Современные мессенджеры (WhatsApp, Telegram и др.) полностью зависят от интернета и централизованной инфраструктуры, что делает их бесполезными в условиях отсутствия связи — на природе, в походах, в зонах чрезвычайных ситуаций (ЧС) или в удалённых регионах.

Цель проекта — создать **автономный защищённый мессенджер**, работающий **без подключения к интернету**, с поддержкой **mesh-сетей**, **сквозного шифрования** и **установки как PWA**.

---

### 2. Цели и задачи

#### Основная цель:
Разработать клиентское веб-приложение для обмена текстовыми сообщениями в оффлайн-режиме с использованием локальных протоколов связи и сквозного шифрования.

#### Задачи:
- Обеспечить работу без интернета через Wi-Fi Direct, Bluetooth Low Energy (BLE) и локальную сеть (LAN).
- Реализовать mesh-логику: каждое устройство может ретранслировать сообщения другим узлам.
- Внедрить механизм прекращения рассылки: получатель отправляет ACK, и все узлы удаляют сообщение из очереди.
- Зашифровать все сообщения с использованием AES-256-GCM и подписи ECDSA.
- Сгенерировать уникальный Device ID при первом запуске.
- Поддержать установку как Progressive Web App (PWA).
- Создать адаптивный минималистичный интерфейс с фиолетовой цветовой схемой и закруглёнными кнопками.

---

### 3. Функциональные требования

| ID | Требование | Описание |
|----|------------|----------|
| FR-01 | Генерация Device ID | При первом запуске создаётся уникальный идентификатор в формате `device_<timestamp>_<random>`. |
| FR-02 | Шифрование | Все сообщения шифруются через AES-256-GCM. Ключ выводится из PSK `"Место Встречи 2025"` и соли через PBKDF2. |
| FR-03 | Подпись | Каждое сообщение содержит цифровую подпись отправителя (ECDSA). |
| FR-04 | Mesh-ретрансляция | Если получатель недоступен напрямую, сообщение пересылается соседям с уменьшением TTL (max = 5). |
| FR-05 | Подтверждение доставки | Получатель отправляет ACK. Все узлы удаляют исходное сообщение после получения ACK. |
| FR-06 | Очередь сообщений | Недоставленные сообщения хранятся локально и отправляются при восстановлении связи. |
| FR-07 | PWA | Приложение регистрирует Service Worker, кэширует ресурсы и поддерживает установку. |
| FR-08 | UI | Отображение статусов (`отправлено`, `доставлено`), маршрута (`напрямую` / `через N узлов`), поддержка светлой/тёмной тем. |

---

### 4. Нефункциональные требования

- **Безопасность**:  
  - Сквозное шифрование (E2EE).  
  - Нет сбора метаданных.  
  - Соответствие OWASP Mobile Top 10.

- **Надёжность**:  
  - Вероятность потери сообщения при ≤3 прыжках ≤5%.  
  - Автоматическая повторная отправка при восстановлении связи.

- **Производительность**:  
  - Задержка доставки: ≤1 сек (1 прыжок), ≤8 сек (3 прыжка).  
  - Потребление энергии в фоне (BLE): ≤5% в час.

- **Юзабилити**:  
  - Время освоения: ≤2 минут.  
  - Минималистичный UI, без декоративных элементов.  
  - Закруглённые фиолетовые кнопки, адаптивная верстка.

- **Совместимость**:  
  - Android 8–14 (полная поддержка BLE + Wi-Fi Direct).  
  - iOS 14+ (только BLE + WebRTC).  
  - Десктопные браузеры: Chrome, Firefox, Safari.

### 5. Исключённые функции

- Передача файлов, изображений, аудио, видео.  
- Голосовая/видеосвязь.  
- Групповые чаты.  
- Интеграция с соцсетями или другими мессенджерами.  
- Использование облачных серверов или внешнего хранилища.

---

### 6. Архитектурные особенности

- **Mesh-сеть**: store-and-forward с TTL и дедупликацией по `messageId`.  
- **Криптография**:  
  - Шифрование: AES-256-GCM.  
  - Подпись: ECDSA на кривой P-256.  
  - Ключи хранятся локально (IndexedDB).  
- **Сетевой уровень**: WebRTC DataChannels (LAN), BLE (мобильные), Wi-Fi Direct (Android).  
- **UI/UX**: React + TypeScript, компоненты в папке `components`, минималистичный CSS.
